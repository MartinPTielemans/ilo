Go straight there
/notifications is the user's inbox. Its filter box takes is:unread, is:read, is:saved, is:done and repo:owner/name.
/search?q=WORDS&type=Issues searches issues and pull requests everywhere. Narrow q with is:pr or is:issue, is:open or is:closed, is:merged, author:NAME, user-review-requested:@me, involves:NAME, label:NAME and repo:owner/name, with + between them. Any of them that takes a user's name takes @me for the user.

Keys beat clicks
On any page: ? lists the page's keys, s or / puts the cursor in search, g n opens notifications.
In a repository: g c opens Code, g i Issues, g p Pull requests, g a Actions.
In code: t finds a file by name, l jumps to a line, w switches branch or tag, b opens blame, and y turns the address into a permanent one, for a line you'll quote.
In a pull request's Files changed: t filters the changed files.

Know before you start
The user can turn single-letter keys off. If a key does nothing, click instead.
Marking a notification done takes it out of the inbox, so read without marking unless the user asked.
